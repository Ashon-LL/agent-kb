# 指令分层：全局只留跨项目通用项，专属坑下放项目级

**经验：** 写 `~/.zcode/AGENTS.md`（全局）时，每条都要过一遍「**换个完全无关的项目，这条还成立吗**」。成立=全局；只对某类任务/某个工具/某个平台成立=写进该项目的 `AGENTS.md`。混分层级的代价是全局文件越来越长、每次会话都注入无关约束、真需要时反而被忽略。

**Why:** 2026-11-01 CTF 项目复盘时，我把三条明显属于「CTF/工具层」的坑写进了全局：
- `fpylll` 在 dim≈768 起段错误 / `fast` 抛 `infinite loop in babai`；
- `PIL` 的 `seek(i).tobytes()` 返回 RGB 不是调色板索引；
- 「平台有没有下发按钮必须点开页面看，不能从 `type_id` 反推」。

用户当场纠正：**「不是所有都要放在全局里」**。这三条离开 CTF/格密码/平台打卡场景就是噪音；而全局文件里真正该有的（授权分级、清理纪律、长任务写法、sudo 探测、子代理边界、会话信息卫生）反而会被它们稀释。

**How to apply:**
1. **判据一句话**：这条约束的适用范围是「所有项目」还是「这个项目/这类任务」？后者一律下放。
2. **全局只收六类**：变更操作要授权的边界、产物位置与清理、长任务/后台作业写法、凭证与信息卫生、工具与搜索的默认选择、全局级已知环境事实（如 WSL 内存配置）。
3. **下放后在全局留一句指针**：`不要把项目专属的坑写进本文件——写进对应项目的 AGENTS.md`，防止下次又把专属坑塞回来。
4. **搬迁要留痕**：搬去项目级时，在项目文件里新建「已知坑（工具/平台层面）」小节，而不是继续堆在原有的长条目里。
5. **自检**：写完全局后通读一遍，凡出现具体库名/维度/按钮名/文件名/某题名的条目，基本都该下放。
6. **过期条目要「连实体一起删」**：删一条全局规则前，先核它指向的实体还在不在（`ls`/`find`/`grep`）。2026-11-01 处理「团队记忆」那条时发现 `team-memory.py`、禁用的 `memory_hooks.py.disabled-*`、配置 `.bak` 三样都还在——只删规则会让人以为东西没了，反过来误调一个连不上网关的脚本；正确做法是规则与实体同批清掉，删完再 `find` 复查。同理，路径类规则（"产物放 X"）先 `ls` 确认 X 还在用，避免把过期路径当规矩执行。
