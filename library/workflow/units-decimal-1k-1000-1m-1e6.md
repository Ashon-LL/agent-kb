# 单位口径：1K=1000，1M=100万（十进制）

## 经验

面向用户写任何数字（邮件、报告、对话、文档）时，K 与 M 一律按十进制理解与书写：

- `1K = 1,000`，`64K = 64,000`，`128K = 128,000`；
- `1M = 1,000,000`（100 万），`1M context = 100 万 tokens`；
- **不要**把它们当 1024/1048576 系（KiB/MiB）换算，**不要**写「64K（65536）」这种括号注换算——用户看了就是错的；
- 确实想说二进制量（如内存 65536 字节）时，写 `64KiB` 或直接写 `65536` / 「6.5 万」，不用裸 K/M。

## Why

- 用户的单位口径是十进制 SI（tokens、价格、计数语境天然如此），1024 系换算在 LLM/网关语境里几乎总是错的：上游报「128K 上限」就是 128,000 completion tokens，不是 131,072；
- 2026-10-29 实例：给用户的更新邮件里写「最大输出请设 64K（65536）」，站主纠正「以后 1M 是 100 万、1K 是 1000」——括号里的换算画蛇添足且口径错误；
- 混用两种口径会让用户对后续所有数字失去信任（分不清哪个是换算错、哪个是事实错）。

## How to apply

- 逢写 K/M 先默认十进制；数字较大时优先用「万/百万」中文表述（12.8 万、100 万），K/M 只在引用上游原文/配置键名时保留原样；
- 引用上游报错或配置值时**原样照抄**（`max_tokens is too large: 384000`），不自行换算单位；
- 需要精度时写出完整数字（64000 / 1000000），别让读者自己算。
