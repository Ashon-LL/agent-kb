**经验**：每接一个新目标（新 SRC / 新任务页），先花几分钟读三样东西再开始探测：

1. **漏洞认定标准 / 无效范围**——决定"我找到的东西算不算"。
2. **敏感数据分级**——泄露类漏洞能不能过，几乎全由这张表决定。
3. **降级与重复判定规则**——决定"是不是白挖"（内部已知的 APP 漏洞通常按重复驳回）。

**Why**：垃圾洞不是白交，是**负资产**。信誉是累积制且只能慢慢缓回——补天信誉值 100，刷洞/一洞多投扣 10、专属 SRC 违规扣 20，累计 ≤60 直接封号，且只能靠"1 个月内无违规 + 有有效漏洞"每月 +1 缓回。多平台联合作战时账号是长期资产，一次误判的成本远高于放弃一条中等质量线索。此外"垃圾洞提交次数多了"本身就会触发平台提示甚至警告。

**How to apply**：
1. 探测前先自问"这个洞落在哪一级"，落「其他数据」或「无」级就直接放弃，别写报告。
2. 判定拿不准就放弃——不要用账号信誉去赌审核员的自由裁量。
3. 报告里主动做**对照组测试**（证明同系统其他接口鉴权正常），把"设计如此"的质疑堵在提交之前，这是把「无效」翻成「有效」的唯一手段。
4. 复盘每个被驳回/降级的洞，记误判原因——这是定级能力唯一的涨法。
5. 判定基准见 [[src-invalid-bug-baseline]]；探测纪律另见 [[alibaba-src-assets-waf-block-probing]]。
