**经验**：

- **可并行**：各子代理持有互不相交的文件集 + 主线先冻结精确 API 契约 + 各自跑构建验证再交付。**不并行**：共享同一视觉语言/同一文件的创作型任务（先主线冻结设计令牌再摊发）。
- **大批量改造前**先给校验器/状态机等纯逻辑补单测，回归会被首跑抓住。
- **子代理半途失败**：成果在上下文里、剩余工作明确 → `SendMessage(原 agentId)` 续跑（点名"不要重做已完成部分"）；重派=上下文全丢；误派立即 TaskStop。
- **禁长 sleep 阻塞**：run_in_background 起轮询脚本，等待期并行做独立工作；区分常驻服务与一次性监控，后台"运行中"≠卡死。
- **并发有上游限流**：批量重跑会触发网关全面限流连锁失败；首跑可并行、重跑小并发串行 + 队列水位控制。
- **验证类任务 prompt 要自包含**（API 用法、异常处置、"遇 paused 先 resume 再判断"、禁改代码只报告）；等确认"真在跑且有输出"再放开下一批。
