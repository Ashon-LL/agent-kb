**经验**：当用户已在自己的编辑器里逐页调好某份生成产物（Word/PPT/网页）并声明"样式我已经真实去看去调了，目前是最适合的"，**该产物即最终稿，其权威高于生成主源（markdown/模板 + 管线）**。此时：

- **不要为改一句文字而重跑生成管线**——重建会用管线自己的排版**覆盖用户的手工调整**（本项目该 docx 已被 Word 重存丢过显式字号与三线表边框，用户仍判定"最适合"，说明其视觉验收优先）。
- 需要改文字时给**可直接粘贴的纯文本**：整句/整段放代码块，**不带 markdown 加粗 `**`、不带 `$…$` LaTeX 标记**；原文该处有加粗的，另行列出"哪几个片段要重新加粗"。
- 提醒两个坑：① 文档里已有数字若是 Word **公式对象**，可只改文字、保留原公式对象，只有新增数字才需打字；② 改动可能撑破容量硬约束（如摘要必须 ≤1 页）时，同时给出"若溢出就删哪一小句"的兜底。
- **版式类**请求（图宽、列宽、表格）→ 告知主源里 `{width=…}` / `<!-- colwidths@N: … -->` 的位置，并说明"重建会覆盖你的手工调整"的代价，**由用户决定要不要重建**；确实要重建就先备份他那份。

**Why**：把用户的手工成果当作可被管线覆盖的中间物，等于毁掉他最在意的工作；我曾提出"提取其 `wp:extent` 回写主源再重建"被直接否决。

**How to apply**：收到修改请求先分两类——**文字** → 给粘贴片段（不重建）；**版式** → 说明主源位置 + 重建代价。若用户明确要求重建，先备份其当前产物再动手。
