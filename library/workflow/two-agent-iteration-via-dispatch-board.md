# 两个 Agent 分工迭代：用「派活板」代替人工转述

**场景**：一个 Agent 改代码/做调研，另一个（人或另一个 Agent）复核。派活靠人工复制粘贴时，
会漏、会走样、对方不知道另一边的进度、历史散落在聊天记录里。

**做法**：仓库里放一个**派活板**文件（本仓用 `docs/dispatch/INBOX.md`），它是唯一的派活入口：

```
## 📌 现在该干什么      ← 派活方只改这里，然后 commit
## 🔄 进行中            ← 执行方开工后挪过来 + 写卡点
## ✅ 已完成            ← 执行方只追加（表里有每轮提交 + 维护者复算结论）
```

**维护约定写进文件头**，避免双方越界：
- 派活方只改「待办」区；
- 执行方只改「进行中」与「已完成」区；
- 双方都通过 commit 交流，**历史天然留痕在 git 里**。

**为什么有效（实测）**：
- 执行方 `git pull` 就知道干什么，**不需要任何人转述**；
- 「已完成」表里带上**维护者的复算结论**（而不只是执行方的自报），
  下一轮直接看到"哪些已核过、哪些是自报"；
- 派活历史与代码改动同 review（`git log` 就能还原"为什么会有这条改动"）。

**配合直连通道**（见 [[cnb-workspace-agent-direct-channel]]）效果最好：
能直连时根本不用派活板（消息即时到达），派活板退化为**给"不在同一时刻"的人/Agent 看的异步档案**。
两者不冲突：即时消息 + 异步档案，各管一头。

**⛔ 派活书里不要写约束清单**（只给：背景与已排除项 / 目标（列候选路径，说"由你判断"）/
怎么算解决（可复算判据）/ 交付）。写太多"不许做 X"会把对方框死，
它会为了守规矩而不做本该做的事（见 [[minimal-change-degenerates-into-skipping-real-bugs]]）。
**明确标注"哪些不许碰"（如涉及产品口径变更的门禁）即可，其余给判断空间。**
