**经验**：长任务（NPC 单 / CI / 长跑测试 / 部署同步）**不要阻塞等待**，也不要靠人反复问"好了吗"。
起一个**哨兵**：后台进程轮询目标状态，**自己判断终态然后 `exit`**，退出时 harness 自动发通知叫我。

## 固定叫法：**哨兵**

用户 20260923 敲定：「现在你开的后台进程，然后这个后台进程能通知你，咱们这个东西叫什么，以后好直接说」
⇒ 「**挂个哨兵**」= 起后台监查进程；「**哨兵响了吗**」= 查通知。适用所有同类场景，不只 NPC 单。

## 三层准确名称（被问过，别答错）

| 层 | 名字 | 说明 |
|---|---|---|
| 工具 | Bash `run_in_background: true` | 起后台进程的开关 |
| 产物 | **后台任务**（background task） | harness 正式术语；有 `task_id`；`TaskOutput` 读；`/tasks` 列 |
| 通知 | **`<task-notification>`** | 进程退出时自动推的系统事件，含 exit code + 输出文件路径 |

## ⛔ 三条失效推论（核心）

**通知的充要条件 = 「进程自己退出」。** 通知不是轮询来的，是进程死了 harness 叫我。

1. **哨兵脚本必须自己判断终态并 `exit`**。写成死循环、或不知道该何时算完 ⇒ 哨兵永不响。
2. **「响」≠「好消息」**：脚本自己崩了也会响。实测：第一版监查脚本因 `cnb` 裸名 `FileNotFoundError` 崩溃，
   通知照发，内容却是崩溃栈。⇒ **收到通知先读内容，别默认"响了=有结果"**。
3. **从 Python 调 CLI 包装脚本要用 `.cmd`/`.ps1` 全名**（Windows `CreateProcess` 不做 PATHEXT 解析，
   裸名 `cnb` 是 sh 脚本 ⇒ `FileNotFoundError [WinError 2]`）。详见 [[cnb-cli-needs-cmd-suffix-when-spawned-from-python]]。
   ⇒ **写哨兵前先想一遍这条**——它是哨兵脚本最常犯的错，且错误形态伪装成"通知内容奇怪"。

**How to apply**：

- 脚本：轮询「目标状态」+ **状态变化才打印**（省得刷屏，也让日志本身可读）+ 出终态即 `exit`；末尾附完整终态快照。
- 轮询间隔 ≥ 目标的最小变化粒度（NPC 单 2min 够）；总时长设上限，超时也要 `exit` 并报 TIMEOUT（否则永不响）。
- 哨兵**只读**：不做任何写/触发操作，避免与目标方的流程打架。
- 目标可能"还没出终态但已有中间产物"⇒ 哨兵可顺带打印分支 sha / PR 列表，让中途核查有据（但仍不抢跑验收）。
- 收到通知后：**先读内容**，再决定验收/续等/处置。

**现成脚本**（mh-agent-open）：`.analysis/watch_npc_sn.py <sn> <branch> [max_minutes]`。
