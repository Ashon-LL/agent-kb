**经验**：当同一个系统（服务器/站点/仓库）会由**多个入口**操作——比如一个人手上的电脑 agent 和手机 agent、或多人多会话——最省事故的做法是维护**一份共享指南**，而不是让各方各自揣着记忆和本地配置。

- **只写当前正确口径**：指南里只写「现在是什么、该怎么做」，历史错误一律不进正文，最多以「⛔ 不要这样」列一行。写错误细节会误导后来者，也会把已被推翻的旧结论固化。
- **指明唯一事实源**：如「渠道/分组/ratio 以线上 X 为准」「代码以仓库 Y 的 main 为准」，避免各方用本地旧值覆盖生产。
- **动生产前先读实时状态**：另一方可能刚改过/重启过；任何变更前先只读核实（GET/状态查询），再动手。
- **改动留痕**：备份 + 脚本 + 提交，让另一方回看与回滚有据。
- **红线集中列**：把「绝对不要动的东西」单独成节，比散落在各条规则里更不容易被违反。

**Why**：2026-11-10 实测——站主同时在电脑（ZCode）和手机（dsh，经 `dsh web` 连服务器）操作同一台服务器/同一个站。若两边各自按自己的记忆改配置，极易出现「一边刚改完、另一边用旧值覆盖」的静默冲突；且手机 agent 扫过全机但对站点业务理解不全，容易做出偏离正确口径的动作。

**How to apply**：
1. 检测到「多入口/多 agent 共管同一系统」时，先建/更新那份共享指南，再派活；
2. 指南放在各方都容易拿到的位置（如服务器 workspace 根目录 + 仓库各一份）；
3. 每次系统状态有变（源上下线、配置口径变、红线变），同步更新指南；
4. 任务结束时检查指南是否仍与实时状态一致，不一致就修。
