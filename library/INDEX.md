## pitfalls/ 教训与反模式
- [并行测试必须先隔离「会写仓库工作树的用例」](pitfalls/parallel-test-run-must-isolate-repo-mutators.md) — 加 `-n auto` 前先挑出变异验证/构建产物类用例并让它们**独占**：并发会读到改了一半的源文件（假红）或同时构建同一份 dist（产物损坏），而「改完就还原」不构成安全（破坏在窗口期内）。落地形态 = 标记 + 两阶段（阶段 A `-m "not <标记>"` 并行；阶段 B `-m <标记>` **不带 `-n`**，互斥由进程边界保证）；⛔ `--dist=loadfile` 不提供互斥；⛔ **`-n`/`--dist` 不许进 `addopts`**（会连用例内部 spawn 的子进程 pytest 一起并行，`returncode` 判据被拖垮）。两坑：兜底哈希快照**未绑定「本会话跑过变异用例」** ⇒ 与后台全量并存时误报「未还原」；**跑测期间改工作树**会当场弄红内容锁用例 ⇒ 先冻结再跑。度量 **13m58s → 7m（≈2×，12 核）**，其中阶段 B 占 57% 是串行成本，别按「总时长 ÷ 核数」估收益。关联 [[file-change-not-code-running]]、[[log-text-is-not-spec-read-emitting-code]]
- [动态工作流的子代理身份与门禁三坑](pitfalls/dynamic-workflow-agent-identity-and-gates.md) — ⛔ `agent(name)` 建在 for 循环里 ⇒ 第二轮同名必炸 `DuplicateActorName`，**代价是整跑中止**（MH-Agent-Open 实测 3h01m / 112.1M tokens、32/32 steps 已 settled 时被打死，交付阶段根本没开始；代码本身没问题，纯脚本缺陷）⇒ 循环内建名带轮次或建到循环外；⛔ **门禁顺序必须让「闸的拦截对象」在过闸前清空**（`sync_to_install` 遇任何 active 工作流即拒，而取证种子恰是 pending ⇒ 正确序：构建→全量测试→铺种子→**路由拦截静态服务验收**（不经安装区）→清种子→同步→性能探针）；⛔ **子代理自述 ≠ 门禁**，取证数据要核对时间戳 vs 所验构建 mtime（实测子代理那份早于最后源码改动），终态必须主代理亲跑复算。附一个真实测量假象：按钮对比度取「矩形内像素中位数」会被**文字像素**污染（同枚按钮两页读出 3.55 FAIL vs 5.40 PASS，而计算样式逐位相同）⇒ 半透明填充分析法算。关联 [[automation-artifacts-lie-existence-and-freshness]]、[[defect-localization-methodology]]、[[subagent-orchestration-lessons]]
- [Tauri 自定义命令的 ACL 三处一致](pitfalls/tauri-app-command-acl-three-places.md) — 每个 `#[tauri::command]` 要被 `invoke()` 调通，命令名必须**同时**出现在：① `generate_handler![]`；② `build.rs` 的 `AppManifest::commands`（漏报 ⇒ **一个 `allow-*` 都不生成**）；③ `capabilities/default.json` 放行 `allow-<命令名>`（下划线转**连字符**：`restart_backend` → `allow-restart-backend`）。缺任一处均**静默失效**（按钮没反应、零报错）；⚠ 判据必须写成**集合对账**，单点断言会在新增命令时**悄悄漏掉**（本仓因此漏了 `restart_backend` 很久）；取证用 `gen/schemas/capabilities.json`（**解析后**的 ACL）或 `strings -a <exe> | grep -c allow-<cmd>`。关联 [[tauri-linux-ci-needs-webkit-41-and-target-override]]
- [校验器 `continue` 掉缺项 = 门禁全绿地漏检](pitfalls/silent-continue-masks-lost-check-coverage.md) — 校验循环里 `if adapter is None: continue` 把「合理缺项」和「键改名了所以查不到（事故）」合并成同一分支：改名后该校验**整个被跳过**，门禁依旧全绿，且零报错。本案 config adapter 键 `codearts` → `codearts__ch177` 后 `compare_adapter_maps()` 对 CodeArts 一行不查，唯一暴露方式是**测试自己 KeyError**（门禁漏检先被测试撞上，不是被门禁发现）。修法 = 精确名优先 + `<键>__<后缀>` 前缀退化，代价为零，收益是以后改键校验**仍然生效**而非无声降级；配套测试断言要跟着改到真实键（否则测的是 KeyError 不是校验逻辑），并保留「注入错误配置必须报错」的用例——**它才是「门禁真在查」的证据**。⛔ 门禁绿只证明没查出错，不证明查过。`OK` 和「我跳过了它」在输出上是同一个字符串。关联 [[broad-oserror-swallow-hides-permission-misconfig]]、[[automation-artifacts-lie-existence-and-freshness]]、[[newapi-rc26-channel-crud-shapes]]
- [New API rc.26 渠道 CRUD 端点形状](pitfalls/newapi-rc26-channel-crud-shapes.md) — ① `POST /api/channel/` 必须 `{"channel":{...},"mode":"single"}`（裸 body → `channel cannot be empty`；漏 `mode` → `不支持的添加模式`），成功响应 **`data=null` 拿不到 id**，须再 `GET /api/channel/` 按 name 反查；② 删除走**路径参数** `DELETE /api/channel/{id}`（`?id=` 是 404 路由不存在）；③ `GET /api/channel/test/{id}?model=X` **要 admin Bearer**（`login` 取 `access_token` + `New-Api-User` 头）——不带一律 401 `AUTH_UNAUTHORIZED`，且**有效/非法模型返回完全一样**，是纯认证墙不是模型信号；模型真被拒时返回 HTTP **200** + `error_code: bad_response_status_code`，真实报错在 `message`；④ ⛔ `GET /api/option/` 的 `data` 是 **`[{key,value}]` 列表**（约 235 项）不是字典，value 是**JSON 字符串**要二次 `json.loads`——按字典解析会得到空值 → 空 PUT → **整表覆盖清空**（曾清空全站 ModelRatio）；映射类 option 必须 GET→本地留副本→合并→PUT 回完整值→回读。通律：**任何写操作后读 `success` 字段，不要只看 HTTP 码**（rc.26 大量「HTTP 200 + `success=false` + 一个字没改」）。关联 [[newapi-base-url-never-carry-v1]]、[[newapi-disable-must-sync-abilities]]、[[newapi-multikey-size-must-track-key-count]]、[[newapi-rc26-token-crud-shapes]]、[[silent-continue-masks-lost-check-coverage]]
- [New API rc.26 令牌 CRUD 三坑](pitfalls/newapi-rc26-token-crud-shapes.md) — ⛔ `POST /api/token/` body 是**扁平**的（不像 channel 要包一层），成功但 **`data=null`、key 不在响应里**；⛔ `GET /api/token/` 列表返回的是**掩码 key**（`MVEN**********q6wu`，18 字符），不是真 key —— 真值只在 `tokens.key`（**裸 48 位、不带 `sk-` 前缀**），所以别写 `assert key.startswith("sk-")`，那会让你在**已经成功的写操作之后**整脚本 abort；幂等脚本要走「先按 name 查存在→存在则复用并从 DB 取值」。⛔ `DELETE /api/token/{id}` 从 `Authorization` 读 token_id 而非路径参数，**恒 `success=false record not found`**，真删只能 SQL 软删 `deleted_at` + 重启刷缓存（重启可能被禁）。⛔ 改 `UserUsableGroups` 别按 key 查模型名——它是「组名→描述串」，模型名在 **value** 里，按 key 查恒 False 而**静默跳过不写**；`ModelRatio`/`CompletionRatio`/`CacheRatio`/`ModelPrice` 才是按 key。⛔ `GET /api/option/` 是全表，很多项 value 是纯字符串，一律 `json.loads` 会 `JSONDecodeError`。关联 [[newapi-rc26-channel-crud-shapes]]、[[newapi-disable-must-sync-abilities]]

- [Tauri Linux CI 需要 webkit2gtk-4.1，且官方 rust 镜像没有 Ubuntu 变体](pitfalls/tauri-linux-ci-needs-webkit-41-and-target-override.md) — 给 Tauri 2 前端加「Linux 上 cargo check」门禁时两层前提必须同时核：① `webkit2gtk-sys 2.0.2` 的 Gir.toml 是 `version="4.1"`，build.rs 探不到 `webkit2gtk-4.1` 的 pkg-config 就 `process::exit(1)` ⇒ 只能用 Debian 13 trixie / Ubuntu 24.04 系；② **官方 `rust` 镜像没有 Ubuntu 变体**（只有 Debian/Alpine，全文 grep `noble` = 0 命中，实测 `rust:1-noble: not found`）⇒ **唯一可用 = `rust:1-trixie`**。⚠ 另一层雷：**仓库里已提交的`[build] target = "x86_64-pc-windows-gnu"` 会让本机 `cargo check` 只编 Windows 目标**，`#[cfg(not(windows))]` 分支根本不进编译图 ⇒ **本机全绿证不了跨平台**；修法是 CI 里 CLI 显式 `--target`（CLI 优于 config），**不要删那个 config**。额外：Debian 包名没有 Ubuntu 的 `-0`（`libwebkit2gtk-4.1-dev` 不是 `-4.1-0-dev`）；`cargo check` 不需要 `frontend/dist` 存在（无需 node，可独立成 job）。关联 [[tauri-remote-url-has-no-ipc]]

- [PS 工具 stdout 恒空，改用「写文件 + Bash 读」](pitfalls/powershell-tool-stdout-empty-write-files-instead.md) — ⛔ **`Stdout: (empty)` ≠ 没跑没输出**（用 `Start-Transcript` 取证：四种输出形式全部产生，回传仍是空）⇒ **只有写文件和 `Exit Code` 两个通道可靠**；写文件必须用 `[System.IO.File]::WriteAllLines(..., UTF8Encoding($false))`（`>` 是截断语义；PS 5.1 的 `Out-File -Encoding utf8` **实为 UTF-16LE**，读回必乱码）；子进程用 `Start-Process -Wait -PassThru` + **两流分指不同文件**可拿全 stdout/stderr/exit code；⛔ `-ArgumentList` 内层双引号会被剥掉 ⇒ 代码写独立脚本文件；⛔ `Start-Process cmd.exe` 与「Bash 调 powershell」两条路都被安全策略封死，**不存在取巧路径**
- [克隆整行会留下模板残留](pitfalls/clone-row-leaves-template-residue.md) — 「克隆现有记录+改几个字段」建配置必然带进模板残留（只覆盖你想得到的）；残留分**有功能影响**（多钥声明数 ≠ 实际钥数 → 重试取不存在的钥）与**纯元数据**（`remark`/`used_quota`/`test_time`/上游模型清单——不影响运行但**界面会原样显示给用户**，本次用户就看见渠道卡片写着别家的「商汤API密钥」「已启用(3/3)」）；检测靠**值重复**（跨记录完全相同的 used_quota/test_time/created_time 即克隆指纹），语义启发式全是假阳性；枚举字段先 `Counter(现有取值)` 查合法集合别造新值；⛔ 别顺手翻转邻接字段（我擅自把两个 legacy 模型 sellable false→true）；交付前列「字段+旧值→新值」表供复核
- [here-doc 进容器必须显式要 stdin](pitfalls/container-heredoc-needs-stdin-flag.md) — `docker exec` 缺 `-i` / `ssh` 缺 `-T` 时 here-doc 静默丢 stdin：**exit 0、零输出、零报错**，极易误判成"代码没执行"；先跑一次 `cat` 探通路
- [PS here-string 定界符语法与运行时字节分岔](pitfalls/powershell-herestring-grammar-and-runtime-divergence.md) — 开闭两侧**不对称**（`'@` 前只准空白 / 后可跟任何东西 / `@'` 尾随空白合法，推翻"header 必须行尾最后字符"的流行说法）、换行符完全无关、`<<` 在 PS 里是**文件重定向**不是未知语法（"Missing file specification after redirection operator." 且后续命令不执行）、**-Encoding UTF8 不是跨运行时修法**（5.1 反而多写 3 字节 BOM，唯一字节一致的是 `WriteAllText`+`UTF8Encoding($false)`）、cmdlet 出口必产生混合换行、一条 stdin 送脚本+载荷 → **0 字节且不报错**、吞变量与真空变量**输出不可区分**（加反斜杠无效且不可自证）
- [bind mount 属主必须匹配容器 uid](pitfalls/bind-mount-owner-must-match-container-uid.md) — 挂载文件的属主由**宿主机**决定，镜像内/容器内 `chown` 一律无效；「宿主机 chmod 600 + 容器非 root uid(10001)」= 容器读不到自己配置、**崩溃循环**，报错只说 `permission denied` 不说 uid 不匹配（易误判成路径配错）；修法 `chown <container_uid>`（600 可保留），验收看"容器真读到了内容"（日志出现 loaded N / listening）而非 `ls` 文件存在；NFS/SMB 改命名卷
- [吞掉 OSError 会把权限错配伪装成「未配置」](pitfalls/broad-oserror-swallow-hides-permission-misconfig.md) — 「可选资源加载器失败就当没有」若在**异常类型层**不区分，`FileNotFoundError`（正常）与 `PermissionError`（配置错误）就成了同一个返回值，auto 回退模式下**配置已部署却不生效、零错误日志**；叠加 `os.path.exists()` 本身吞异常 = 双重静默。排查顺序必须是 `systemctl show -p User` → `/proc/<pid>/environ` → `stat` 整条路径链（每级目录都要可遍历）→ **以该 uid 身份实测 open()**，**先于怀疑自己刚写的代码**；unit 文件内容不等于运行身份，以 `systemctl show`/`/proc` 为准。修法：加载器只吞 `FileNotFoundError`/`ValueError`，其余 `OSError` 冒泡打日志（回归测试用「路径是个目录」造 `IsADirectoryError`，跨平台不依赖 root）；回退日志必须写原因；部署上优先给服务**自己拥有的**目录而非放宽全局 secrets 目录，必须给目录权限时**只给 x 不给 r**（能按名打开、列不出目录、读不到同目录其他私密文件）；验证部署看「用了哪条路径」而非「功能有没有坏」
