# 「出处」写错三连：未见记录当不存在、4 个样本编 P90、来源一致当条件成立

**现象**（2026-10-05，用户当面纠正）：我在文档与界面里为一批默认值做「溯源考古」，
把三处**推断/未见记录**写成了**事实**，用户回复：

> **「不同的来源可能有不一样的限制，不一样限制又可能有不一样的条件。所以来说，
> 你不能轻易地去假设，而且不能用猜测的假设作为接下来的依据，即便假设被验证确实，
> 也有可能是不对的。」**

**四个实错（同一病根）**：
1. **「未见记录」写成「不存在」**：四只设置键我写「无实测出处」。实际是**对照上游项目
   补齐同名机制**（上游可见值与我方一致 ⇒ 推断承自上游）；我甚至**连键列表都列错**
   （漏了一个、混入另一个）。「我在手头材料里没找到记录」只说我的搜索范围，不是世界的属性。
2. **小样本编分位数**：4 个样本（3.7 / 21.2 / 12.0 / 26.6）我写成「P90≈27min」——
   4 个点算不出 P90，27 只是**最大值**。分位数/均值等统计词在样本量不够时一律不许用。
3. **把逐项不同的条件压成「统一语义」**：我写「统一：阈值在步骤启动时读入（快照语义）」。
   实际逐键不同：步骤/会话级=步启动时读；检查点=每 60s 巡检**重读**；并行数=调度时读；
   复活上限=仅启动扫描读。触发后果也逐键不同（暂停/自动放行/判失败/排队）。
   **「统一」「全部」「一律」这类词出现时必须逐项列表复核**——有一项不同就是错。
4. **界面上宣称未考证的来源**：UI 写「默认值是经验值」——「经验值」本身也是一处
   没考证过的溯源声称。**界面对未经考证的来源，一个字都不要写**。

**怎么防**：
- 写「出处/来源/为何是这个值」类表述，强制三档：**事实**（有可核物证，注明出处行号）/
  **推断**（写出推断链与置信边界，「值一致 ≠ 已证移植」）/ **未见记录**（原样写「未见记录」，
  ⛔ 不写「不存在」「无出处」）。
- **来源一致 ≠ 条件成立**：即便确系移植自上游，也不得推出「在本环境（换了执行器、
  框架、负载）下同样合适」——条件不同的取值不可互推。
- **「验证过」也要带条件**：结论要连条件一起写（在什么版本/执行器/负载下验证的）；
  条件变了结论要重新验证。
- 复核动作：对「统一/全部/一律/都」类词做**逐项列表对照**；对数字做**样本量 sanity check**
  （要 P90 就先看有没有 ≥10 个样本）。

**同族条目**：`volatile-state-must-carry-expiry-and-recheck`（易变状态要带时效与复核命令）、`runtime-anomalies-may-be-operator-actions`（把「与预期不符」当故障）、
`config-field-name-is-not-spec-read-consuming-code`（字段名不是规格）、
`handbook-commands-must-verify-consuming-code`（手册凭记忆写 3 处错）。
