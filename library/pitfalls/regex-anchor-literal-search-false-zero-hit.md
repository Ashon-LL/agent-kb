# 含正则元字符的检索词作证据必须加 -F

## 经验

用 `rg '<pattern>'` 的「零命中」去证明「全仓无消费点/无写入方」时：若 pattern 含 `$`、`(`、`[` 等正则元字符（例如检索 `$FORMAT`、`$LANGUAGE` 这类变量名），**必须加 `-F`（或 grep 加 `fgrep`/引号转义）按字面量匹配**，并在证据里注明用的哪种模式。默认模式下 `$` 是行尾锚点，`rg '$FORMAT'` 恒零命中——你会把「正则语义必然匹配不到」误报成「代码里不存在」，整条审计结论失效。

## Why

2026-10-22 审读 MH-Agent-Open 软件审计汇总时发现：P2-51 条目以「rg 全仓无 `$FORMAT`/`$LANGUAGE` 消费点（0 命中）」为唯一证据得出「预设参数未接线」的 P2 级结论——但 `$` 在默认正则模式下是行尾锚点，该检索式**无论代码里有没有这些变量都恒零命中**。同类陷阱还有：把 `(xxx)` 当字面串检索（正则里是分组）、`.` 通配任何字符造成**假命中**反方向的误报。零命中证据的杀伤力恰恰在于它「看起来最干净」，没人会怀疑检索式本身。

## How to apply

- 任何把 grep/rg 命中数（尤其 0）写进审计报告、门禁判据、PR 描述前，过一遍 pattern：含 `$ ( ) [ ] . * + ? | ^ \` 即切 `-F` 或转义。
- 证据行注明模式：`rg -F '$FORMAT'` 与 `rg '$FORMAT'` 是两个不同的实验，前者才是「代码里没有这个字面量」的证明。
- 复核别人的零命中结论时，第一步先重跑检索式本身（加 `-F` 对比命中数），再去看代码。
