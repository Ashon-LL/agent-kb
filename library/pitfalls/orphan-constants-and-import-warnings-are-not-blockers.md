**经验**：一条报错/一个常量"看起来是问题"，和它"是不是真的阻塞"，是两件事。
判断前必须先 `grep` 它的**实际使用点**。

## 症状（真实案例）

在容器里跑应用，日志出现：

```
Claude CLI 未在任何已知路径找到（…四个候选路径…），使用占位路径 …；
请重新安装 runtime 或在设置中指定 claude_cli_path。
```

当时我的结论是「**该容器缺执行器，跑不了实弹**」。**这是错的**，害得用户反问
"我不是已经换成 openclaw 底子了吗，为什么还有 claude cli"。

## 真相（逐条 grep 后得到）

| 问题 | 答案 |
|---|---|
| 告警出自哪 | `config.py` **模块级代码**，`import config` 时**无条件执行** |
| 它读「当前用哪个 harness」吗 | **不读** —— 用 openclaw 还是别的，它都跑 |
| 拦住什么了吗 | **没有**。纯 `logger.warning`，不 raise、不 return |
| 那个常量被谁用 | **全仓库零使用点**（只有定义行 + 自引用 + 一条 import） |
| 活跃路径查这个 CLI 吗 | **不查** —— `if harness == "openclaw":` 分支里零命中，只查它自己的依赖 |

⇒ 它是**历史遗留的无害告警**。而且日志里紧随其后就是 `code: 0` 和成功产物。

## 可复用的判据

**判断「X 是否是阻塞项」的三步：**

1. `grep -rn "SYMBOL" <源码根>`，**排除**定义行、自引用行、`import` 行。
   - **没有第三处命中 ⇒ 它不是阻塞项**（死常量/纯告警）。
2. 看报错是 `warning`/`logger.*` 还是 `raise`/`return None`/非零退出。
   - 只看不抛 ⇒ 通常不阻塞。
3. 找**活跃路径**里的分支（如 `if mode == "X":` / `else:` 两半分别看）
   —— 是否真的会走到它。

## 更上位的一条纪律：两层证据

同一轮里我还犯过一次同类错误：看到 `Prepare` 阶段 success，就断言
「密钥库凭据已注入」。**也是下得太满** —— `Prepare` 过只说明**引用未被拒绝**，
不证明**变量真的注入**。

⇒ 凡是判断「链路是否通」，必须锚定**终点可观测物**，不能拿中间态当结论：

| 层级 | 例子 | 能否作为结论 |
|---|---|---|
| 中间态 | `Prepare` success / 进程 exit 0 / 依赖 import 成功 | ❌ 只能说明"没在这步失败" |
| 噪音 | import 期告警、deprecation warning | ❌ 通常无关 |
| **终点可观测物** | 目标产物真的存在且内容正确 / 环境变量名单齐全 / 断言通过 | ✅ |

**How to apply**：汇报前自问「我这条结论的**证据**是终点还是中间态？」
如果是中间态或噪音，降级为「未验证」，或去把终点证据取到手再下结论。
⛔ 尤其**不要在汇报里把噪音当阻塞项**——它会把用户带偏，浪费一轮沟通。

## 续：删除这类"死分支告警"后，怎么写**抓得住**它的网眼（20260918 变异验证教训）

清理掉这坨孤儿代码后我补了回归网，并在**变异验证**时踩了两个新坑 —— 都很通用：

### 坑 A：**环境依赖型假网** —— 网眼只在特定主机上有效

原实现是：

```python
if not any(p and p.exists() for p in _CLAUDE_PATHS):
    logger.warning("Claude CLI 未在任何已知路径找到…")
```

我写的网眼是「子进程 import config，断言没打告警」。**在开发机上永远绿** ——
因为本机装了 runtime，4 个候选里 2 个真实存在 ⇒ `not any(...)` 恒为 `False`
⇒ **告警分支是死代码**。于是我把常量改回去做变异，网眼**没能变红**。

⇒ **判据**：写"某行为不该发生"的网，必须先确认**该行为在跑测环境下本来就会发生**。
   否则测的不是实现，是环境。

✅ **正确做法（两种互补）**：
1. **静态网（AST，与主机无关）**：直接 parse 源码，断言模块顶层没有
   `Name = ...` 目标为禁名、没有携带告警文案的 `logger.warning(...)` 调用节点。
   —— 不看文件系统，任何主机一样硬。
2. **强制构造成立条件的行为网**：把触发条件**人为置真**再执行。
   本处做法 = 把源码里候选表用正则替换成"保证全不存在"的路径表，
   再 `exec(compile(src2,...), mod)` 跑一遍模块代码，捕获日志断言为空。

### 坑 B：**注释里逐字引用文案 ⇒ 朴素子串扫描必然误报**

释义注释里写了 `logger.warning("Claude CLI 未在任何已知路径找到…")` 来记录删除理由，
于是 `if "Claude CLI 未在任何已知路径找到" in src:` **在干净代码上也报红**。

⇒ **判据**：凡是"文案不得出现/必须出现"的断言，
   若目标文件里**有解释性注释会引用该文案**，就不能用子串扫描。
   **改用 AST**：只看 `ast.Call` 节点（真调用），注释天然被排除。

### 顺带：断言的**方向**也要选对

`exec` 注入式行为网里，我一开始断言 `"__SRC_HAS_WARNING__False" in stdout`。
**写反了** —— 若哨兵根本不存在，这条断言会因"没找到"而误红；
应断言 `"__TRUE" not in stdout`（**否定式**），语义才对得上"不得出现"。

**How to apply（写"防复活/防回归"网眼时的自检四问）**：
1. 这条断言在**干净代码**上绿吗？（不绿 = 假阳性）
2. 把实现**改坏**（变异）后**红**吗？（不红 = 假网眼）
3. 它依赖**跑测主机的文件系统/环境**吗？（依赖 = 至少补一条静态网兜底）
4. 扫描目标里有没有**注释/文档会引用同一段文案**？（有 = 必须用 AST，别用子串）
