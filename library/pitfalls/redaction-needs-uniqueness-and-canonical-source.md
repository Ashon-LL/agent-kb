**经验**：把密钥/令牌改成 `sk-660...975e` 这种"保留前 6 后 4"的遮蔽时，动手前先跑一次**遮蔽值碰撞检查**（`len({mask(k) for k in keys}) == len(keys)`）；并把"全量值"和"脱敏版"在物理上分开：`docs/` 只放脱敏版，**投递包/归档里放全量版**，两边都写明口径、并明确禁止用脱敏版重新打包。最终自检必须复扫**全项目所有文本文件**，而不是只扫刚刚编辑的那几份。

**Why**：三个独立失败点，任何一个都能让"已脱敏"变成假安全或不可用：

1. **遮蔽碰撞**：189 个密钥按 6+4 遮蔽后若不唯一，两份报告里就会出现两行同形密钥，收方拿着遮蔽值对不上账户、也分不清是哪一条要吊销。本次实测 189 → 189（0 碰撞）才动手，属于"先验证再执行"的最低成本。
2. **脱敏把可执行性删掉了**：泄漏通报的价值是让厂商能定位并吊销。docs 版遮蔽后，全量值必须还在某个**单一封包**里（本次是 `tmp-scan/report-<vendor>.zip`，内含全量报告 + 完整清单 JSON）。若只做脱敏不留全量源，报告就变成"不可执行的通知"。
3. **自检覆盖面造假**（最危险）：上一轮"明文密钥残留 0"的自检只覆盖了当时新写的 3 份文档，而真正的交付物 `docs/report-*.md` 里躺着 193 处明文、`grep` 一扫就出。**结论对不对，取决于扫描范围**：自检脚本要按「全项目 + 排除唯一允许存放明文的那一个目录」写死，而不是按"本次改过的文件"列。

**How to apply**：① 遮蔽前先算碰撞（一行 set 长度对比），碰撞则加长前缀/后缀；② 固定"唯一明文区"（如 `tmp-scan/`），其余目录一律脱敏，并把这个边界写进项目规则；③ 全量版封包后**不要再用脱敏版重打**，两处都留一句口径说明（"zip 是唯一投递载体"）；④ 收尾自检用全项目正则扫 + 白名单目录，输出"命中文件 + 次数"，0 才算过；⑤ 改动前留一代备份（含明文的老版本放行区），确认无误后再删——回滚源与投递包是两回事，别互相顶替。

关联 [[redaction-must-key-on-field-not-value]]（按键名判定 + 负向自测）、[[over-redaction-removes-useful-context]]。


## 2026-11-10 补：宽松正则 + 全目录通杀会毁掉二进制载荷（来源 zcodepro 2026-11-09）

**同一事实的新反例，扩充本条**：脱敏不只「遮蔽得对不对」，还要看**扫描范围与命中模式是否会把非文本载荷改坏**。

实测（本机 session_6740b533）：一次性手工脱敏脚本用
`re.compile(r'(sk-[A-Za-z0-9_-]{8,}|ak_[A-Za-z0-9]{8,}|HKp[A-Za-z0-9]{8,})')`
对 `~/.zcode/cli/artifacts|rollout|log|exec` 全目录 `*.txt` 逐文件 `pat.sub(lambda m: m.group(0)[:3]+'***', s)`。
图片 artifact 是 `data:image/png;base64,…` 文本，base64 里恰好出现 `HKpUCYNLGjRvp7…` 这样的长串，
被当成密钥把 80 个字符换成 `***` → base64 非法 → 多家 LLM provider 同时回 400 `Invalid base64 data`，
Turn 与 Compact 全挂。实测污染 279 个图片 artifact / 23 个会话，损坏件 mtime 精确聚在脚本运行时刻。

**How to apply（补）**：① 脱敏脚本必须按键名/字段名判定（见 [[redaction-must-key-on-field-not-value]]），
不要拿「长得像密钥的值」在全目录里正则通杀；② 显式排除编码载荷：
`data:image/*;base64,`、`.pem`、二进制、图片缓存；③ 改前对目标文件做**可解码性校验**，改后复验
（图片 base64 要能 `b64decode(validate=True)` 且魔数正确）；④ 先备份清单 + 全文件内容，留回退点；
⑤ 归因时别把「多家服务同时拒收」当成上游问题——先查请求数据本身。
