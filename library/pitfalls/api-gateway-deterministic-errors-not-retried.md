**经验**：把上游错误分「确定性」与「瞬时」两类，**确定性错误一律不可重试**（RetryTimes=0），
只有瞬时错误（5xx/超时/连接类）才进重试预算。重试预算必须与「源内换号数」**相乘**着算最坏值：
最坏上游调用数 = 重试次数 × 可换账号数。常见反例是 RetryTimes=10 再叠加源内换号 3 个
⇒ 单次用户请求最多打出 30+ 次上游调用，把一次可恢复的抖动放大成上游侧的异常流量。

**Why**：确定性错误（参数错、模型不存在、无权限）换号也不会好，重试只是把同一个失败重复 N 次；
而换号会把「同一个失败」复制到多个账号上，既放大上游压力，也让自己的限流/风控计数器被自己打满
（2026-10-26 参考工程审计：本站曾把 RetryTimes=10 与源内换号叠加）。

**How to apply**：给每个源维护一张「错误类别 → 是否重试 / 是否换号 / 是否写冷却」的表；
新增错误码时先判它属于哪类，再决定进不进重试预算；压测或事故复盘中按
「重试次数 × 账号数」核对最坏放大倍数。
