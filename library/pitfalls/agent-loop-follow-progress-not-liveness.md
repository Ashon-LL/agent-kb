**经验**：跟进一个自主 agent（或任何自驱循环）的长任务时，"它还活着"≠"它在推进"。三条硬规则：

1. **提示词层护栏一律视为不存在**。给模型写的"预算 N 轮、连续失败 2 次禁重试、超出即收口"只是建议——模型状态一复杂就会无视，且**无视时没有任何东西会掉**。凡约束必须有人在引擎侧计数并强制中断；审查代码时"该约束由谁执行"答不出"引擎"俩字就当缺陷记。
2. **静默型看门狗防不住"响着不收敛"**。mtime / no-output / 心跳类超时全键在"没动静"；模型反复改文件、每 30s 吐心跳的 thrash 永远满足"有动静"。补位度量：**同一错误串/断言指纹在窗口内重复命中 N 次**、**单位时间交付物（文件数/测试通过数/入库数）为零但调用量高**。
3. **汇报"在收敛"前先重判进展，并给自己设最大关注时限**。判"在变近"的代理指标=失败计数是否停止增长、错误是否变化、剩余步数是否单调降；每次"还在跑"的汇报前重算一次。轮询盯守必须带**成本 checkpoint**（token/金额/时长到阈值即主动核实或中断），没有时限的守望等于没守望。

**How to apply**：接手"帮我跟进跑完"类任务时，先确认护栏由谁执行；监听器只挂"跃迁/终结"会漏掉中间态恶化，必须另加"最大守望时长→强制人工核查"的兜底；发现响循环先暂停止血（可逆）再归因。
