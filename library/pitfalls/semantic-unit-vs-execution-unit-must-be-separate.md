# 「阶段」与「执行单元」被压成一个概念，必然撑不住

**现象**（2026-10-20，用户指出走偏）：
工作流引擎把「步骤」同时当成两样东西——**人讨论的语义单元**（调研/写作/质检）与
**执行单元**（一次 harness 回合 + 一份产出契约 + 一道门禁；**默认由常驻会话承载**，一次性 `exec` 只是逃生阀）。用户原话：
「一个工作流仅有那几个技能来构成步骤，是残缺的」，正解应是
「工作流由多个阶段构成，一个阶段里可以有多个技能」。

**两条可验证的代价**：
1. **变体爆炸**：写作能力被拆成 `paper-write / -docx / -nature / -nature-docx / -zh /
   -zh-docx` + `comp-paper-{en,en-docx,zh,zh-docx}` = **10 个技能**，本质是
   「写作 × 语言 × 输出格式」的笛卡尔积（再加期刊模板/字数档位就是 30 个）。
2. **身份撞车**：`skill_name` 被当步骤主键（`/steps/{skill_name}/rerun|skip`）
   ⇒ 同一流程不能出现两个同名技能步骤，一步也装不下第二个技能。

**怎么修（关键：加语义层，不动执行层）**：
- 新增一层「阶段」：`工作流 → N 阶段 → 每阶段 M 个执行单元`，**执行单元语义零改动**
  （仍是一会话、一契约、一门禁、不并发）——改地基会连锁改引擎核心；
- **零语义漂移**是硬要求：未声明阶段的步骤自成阶段、存量回填用**一次性标记位**、
  展示层只在「多单元的阶段」才渲染新 UI、序列化只在显式声明时才写新键
  ⇒ 存量数据行为与界面逐字不变（可被逐字节 diff 验证）；
- 聚合口径要单点定义（阶段状态 = 子单元最严重者 / 进度 / 产物并集）；
- 阶段用**数字下标**寻址，别用显示名（会被 URL 编码、改名即断链）。

**最容易漏的一处**：**创建路径**。数据层加了新列、模板声明了新字段之后，
若「模板 → 落库」的中间构造没带上该字段，就会出现
**老数据正常、新建数据全丢**的隐蔽形态（存量回填掩盖了它）。
⇒ 修完必须用 `inspect.getsource` 之类的**静态反锁**把创建路径钉住，
而不只是测「数据层能写这个字段」。

**关联**：[[local-sync-must-reach-user-visible-layer]]（同一个教训的另一面：
只看自己这一层的产物不够）；同项目记忆：阶段模型专条。

## 附：判「默认走哪条路径」必须找判据唯一出处（20261020 我栽过）

同一次会话里用户连问三次（「不是 exec 吧？」→「为什么还是默认走 exec？」→
「我们不是很久之前就放弃 exec 了吗」），前两次我都拿 `harness/*.py` 里的 argv 构造器
（`build_command` / `SUBCOMMAND_EXEC`）反推默认路径，结论**全错**，还写进了注释/文档/记忆。

**根因**：argv 构造器只是「某条路径怎么拼」，不等于「默认走哪条」。
默认值往往在另一个**判据唯一出处**（这里是 `services/gateway_session.hosting_enabled`
—— `gateway_session_enabled` 未设即开、显式 `0/false/no/off` 才回落 exec）；
而且这次连 `decision-changelog` 里都已有留痕（「引导**去 exec**默认为开」）。

**可复用的查法（三步）**：
1. 搜「开关/判据」而非「实现」：`hosting_enabled`、`*_enabled`、`resolver`、`DEFAULT_*`；
2. 读它的 docstring 里有没有「默认值反转 / 用户裁定 / 留痕」这类字眼——有就说明这里才是权威；
3. 用**运行态**印证（如容器 `settings` 里该键的实际值），别只看代码。
⛔ 用户的口头记忆与代码冲突时，先假设**自己对代码的读法可能有偏差**，去找判据出处，
而不是拿构造器反驳用户。
