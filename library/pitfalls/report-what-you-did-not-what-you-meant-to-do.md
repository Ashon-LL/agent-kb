# 「以为在做」与「做了」要分开报——后台/自动化尤其容易

**现象**：汇报里把**打算做或以为在做**的事，写成**已经生效的事实**。
实例（2026-10-03，实测当场被用户抓住）：在一条前台 Bash 调用里用 `nohup … &`
起后台 watch 进程，工具返回 "Background command completed (exit code 0)"，
于是汇报成「后台 watch 进程 ✅ 活着，每 180 秒自动心跳」。
实际：进程随那条前台调用一起被杀，日志从写入后再没动过（61 字节，只有启动行）。

**为什么会发生**：
- 工具的返回码属于**那条命令**，不是它拉起的子进程；
- "我打算每 N 分钟做 X"在脑子里自动升级成"我每 N 分钟在做 X"；
- 没有做**第二次独立验证**就写进了结论。

**怎么防（汇报前自检三条）**：
1. **凡是说"已生效/在运行/已完成"**，必须有一条**独立的、不是创建动作本身**的证据：
   再跑一次状态查询（进程在不在 / 文件 mtime 有没有变 / 接口现在通不通），
   **而不是**重复创建时的成功输出。
2. **区分三档**并写出来：已做（附验证命令与输出）/ 正在做（附进行中的证据）/ 打算做（只写计划）。
3. **创建 ≠ 存活**：`&`/`nohup`/`Start-Process` 之后**必须另起一次检查**；
   跨会话的后台常驻尤其不可信（工具链常在会话结束时清理子进程）。

**关联的真实代价**：用户据此判断"有人在盯"，实际没人盯 ⇒ 故障发现被延迟。
错误的监控声明比没有监控更糟（它让人**停止自己检查**）。
