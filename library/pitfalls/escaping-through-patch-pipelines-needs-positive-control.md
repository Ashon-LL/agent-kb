**经验**：不要用「生成脚本 + heredoc」把带转义的代码写进文件 —— 反斜杠序列（反斜杠 b / n / t）
在传递过程中可能被**写成真正的控制字符**（反斜杠 b 变成 0x08 退格、反斜杠 n 变成换行），
写进去的代码**看起来对、跑起来也不报错**，但语义已经变了；更糟的是它专门破坏「校验/检测」类代码，
让本该拦住问题的断言**静默失效**。

**Why**：APIShow 的上游项目汇总里有一条「表里不许写凭据」的断言，正则用了
「词边界 + 关键词 + 赋值」的形式。经过一层补丁管道后，词边界标记变成了**退格控制字符**，
正则退化成宽松匹配 —— 而它当时「通过」了，看起来一切正常。转折点是给它补了一条**正向对照**
（拿一个假凭据试：`api_key: "wbk_可识别的一串"`）—— 结果**漏报**，才暴露出正则已经坏了。

同类事故在同一次任务里发生了 **3 次**：注释里的换行/制表转义也变成了真换行与制表符，
把一行注释拆成三行并触发 TabError；**连记录这条教训的 kb 条目本身也被同样污染了一次**
（写完发现文件里真有退格和制表符、索引行被拆成两行、还带出一个未闭合代码围栏）。
可见这不是偶发，是这条路径的固有属性。

**How to apply**：
1. **凡写正则/转义，必配正反对照用例**：一条该抓到的（假凭据）+ 一条不该抓到的
   （端点名里带 password 不算凭据）。**没有对照的校验代码等于没有校验** —— 它坏掉时不会告诉你。
2. **写这类内容时避免反斜杠**：用 `[^A-Za-z0-9_]` 代替词边界、用 `[ ]*` 代替空白类、
   用 `chr(10)` 代替换行转义。零反斜杠的等价写法照样能写对。
3. 写完立即**机检控制字符**：对源码取 `ord(c) < 32` 的字符集合（排除正常换行/回车/制表），
   断言为空；**顺便覆盖注释**（注释被拆行也会被抓到）。
4. **优先用编辑工具直接改文件**，而不是「脚本生成脚本」；必须用脚本时，改完一定回读校验。
5. 渲染类产物（文档/表格/邮件）同理：生成器写坏了只会"少几行"，不会报错 —— 所以要有
   「产物与事实源同源」的断言（本项目的 `upstream_index.py` 就是这样被单测锁住的）。
