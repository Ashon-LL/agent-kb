## 经验

逐帧动画里给 N 个同族元素做错峰入场时，窗口的**起点和终点都必须随索引 n 后移**：

```js
// 错：终点固定 → n 大到起点 >= 终点时，seg  clamp 到 0，元素永远不画
seg(p, .1 + n*.006, .4)
// 对：终点跟着起点一起走，每格保留同样的错峰窗口宽度
seg(p, .1 + n*.003, .24 + n*.003)
```

写完后按最末元素验算：`a + (N-1)*step < b + (N-1)*step` 必须成立且终点落在幕内（如 p≤.6），否则末段元素恒透明。

## Why

索引越大起点越晚，一旦 `a+n*step ≥ b`，`seg()` 的 `(p-a)/(b-a)` 分母为负或分子恒负，easeOut/clamp 后恒为 0，元素整幕不显示。若这些元素是「100 格里 12 格涂橙表示 12%」这类**统计示意**，实际只画了 42 或 50 格，12 橙就变成 24% 或 28.6%，与屏上数字直接矛盾——是比漏画更危险的**数据说谎**。本例关键帧门禁 0 ERROR 也没抓到，因为机械检查只看空/满/出界，不看「该出现的格子数量对不对」。

## How to apply

- 写错峰公式时先算末元素窗口，确保终点>起点且在幕内；用「窗口宽度固定，整体平移」的写法。
- 凡是**用数量表达比例**的点阵/网格/车列，成片抽帧必须数一遍实际显示的元素个数，并和标注的百分比对照；不能只靠静态关键帧门禁。
- 与 [[video-review-and-acceptance]]、[[video-review-and-acceptance]] 配合：门禁过 ≠ 数量对，成片抽帧要看统计示意元素的实际数量。
