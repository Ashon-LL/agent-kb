**经验**：模型权重/数组文件里"每层只有 14/12/10 种不同行、宽度 48/40/32"这类重复结构，
能可靠给出**尺寸与数量**，但给不出题目声称"被打乱"的**顺序**。当答案恰好是三段
长度等于隐层宽度的索引序列时，正确姿势是把结构当"宽度线索"，去猜**顺序来自 PRNG**：
权重由一个种子生成、"摇匀"用的置换来自同一条流的下一个种子。

**Why**：重复行/列只定义等价类（分组），任何组内置换和组间重排都不改变"重复结构"。
把分组标签、原型编号（偏置序/字典序/范数序/组大小序）和各种排序置换当候选去撞哈希，
候选空间看着大（实测枚举 200 万+ 规范串）但全是同一类假设，必然 0 命中。
真正的顺序信息在流里：出题人用 RNG 生成权重 + 用 RNG 生成置换，种子通常是日期。

**How to apply**：
1. 先统计 `元素数 / 唯一值数`：唯一值远小于元素数 ⇒ 权重来自"候选池 + 按索引取用"，
   不是逐层独立采样；再用 `np.unique` 池子大小反推一次性 `normal(0, σ, N)` 的 N。
2. 取某张量的一整行（长度 ≥ 32）当**指纹**，对候选种子做 `np.array_equal(row, samples[:k])`
   ——float64 精确相等、无容差；再用 `np.setdiff1d(所有唯一值, samples).size == 0` 做
   **全池覆盖**二次判据，两条同时过才算命中（单靠覆盖易误配）。
3. 种子候选按**日期**枚举（题面发布前后 1~2 年足够），命中通常唯一；密码学/其它比赛同理，
   题号、时间戳、`YYYYMMDD` 都是低成本候选。
4. 置换用**相邻种子**（±1~7 天内扫一遍）`rng.permutation(48/40/32)`，拼规范串后先用题目
   自带校验脚本里的硬编码常量自证（用正则从 check.py 解析，别硬编码）。
5. 复验走第二条路：把随机流按"表 → 偏置 → 表 → 偏置"分段（段长 = 类别表大小，行间可能夹
   未使用填充值），用"值集合"匹配回原型行，能**逐元素重建**整个模型即证明种子就是生成器。

**检索症状词**：权重被打乱、置换索引、神经网络权重 shuffle、唯一值数远小于元素数、
种子枚举、日期种子、default_rng normal、答案是三段索引、check.py 硬编码 V。
