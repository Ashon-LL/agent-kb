**经验**（判定顺序：先看数据分级，再看利用性，最后看重复）：

1. **官方【无】级 = 0 分值**：功能缺陷/乱码/样式/兼容性；无法利用的漏洞（Self-XSS、无敏感操作 CSRF、无意义的异常信息泄漏、内网 IP/域名泄漏、管理后台泄漏、默认 demo 未删、无敏感信息的 SVN、仅小众固定浏览器可触发的 XSS、邮件轰炸、轮循式短信轰炸）；纯属猜测、不能直接反映漏洞存在的问题。
2. **敏感数据分级决定泄露类能不能过**：极度敏感=证件照片/核心账密对/生物识别；重要敏感=**三元组或以上**（姓名+手机+地址/银行卡）、AK-AS、核心服务器与库账密；次重要敏感=账号名+邮箱+生日/性别三元组、核心电商买家浏览收藏记录。
3. **⛔「其他数据」= 可能低等级接收或直接驳回**：商家信息（证照、联系人、**联系方式**、银行账号、地址、营收）、仓储物流信息、个人设备信息、会员等级/积分、互动信息、地域信息。**门店电话、商家地址、POI 坐标这类半公开经营信息，默认不收**——实战教训：263 家门店手机号+地址+坐标免登录全量返回，证据链完整、报告写完，仍被判"不算"，因为它落在「商家信息-联系方式」且不构成三元组。半公开信息泄露 ≠ 敏感信息泄露。
4. **九条降级规则**：需交互的利用降级；有前置限制（如需先爆破 6 位验证码）降级；影响用户量极小降级；部分环节重复降级、全部重复按重复驳回；利用链路复杂/需结合爆破/有时间成本降级；**只说理论可行、没给成功案例 → 降级（必须有实跑证据）**；仅非 Chrome 可触发的 XSS/JSONP 最高低危；URL 跳转需登录或固定域名降级；内部已知的 Web 漏洞正常确认但**内部已知的 APP/客户端漏洞按重复驳回**。
5. **平台不通过的五种理由**：无法复现；真实存在但危害较小；抄袭或未经验证；厂商太小/已停维护；与平台记录重复或细节已在互联网公开。

**Why**：判定基准是公开文件，但没人会主动告诉你——多数白帽是交出去被驳回后才读到。

**How to apply**：动手前先拿目标 SRC 的分级表对着自问一遍；报告落笔前问"我拿到的是三元组吗""它公开吗""我有没有实跑证据"。红线另计：泄露报告细节、一洞多投/成交后公开、实质性非法入侵（TSRC 已通报取消奖励+官网点名；MiSRC 有取消全部奖励并保留追责的案例）会直接清仓。

## 三层判定模型（2026-09-22 增补，源自 gh Kedibin-Win/pentest-skill）

**核心口诀**：接口能调通 ≠ 有漏洞；返回 200 ≠ 确认漏洞；不带认证 ≠ 越权；有返回数据 ≠ 信息泄露。

标 `confirmed` 前强制过三层：
1. **可达性** Access：能调到接口吗（200/code=0）——**只过这层只能标 suspicious，不能 confirmed**
2. **脆弱性** Vulnerability：返回的是「不该给当前请求者看」的数据吗（公开字典/系统时间/空列表/格式校验结果不算）
3. **可利用性** Exploitability：危害真实落地了吗——越权读必须拿到**他人的**私有数据（姓名/手机/余额/订单），越权写必须确认库或列表**真变了**，不能只看 `{"code":0}`

过第 2 层但第 3 层不足 → 降级或 needs more proof。**这就是「没实跑证据只说理论可行就降级」的可执行版本。**

**默认不报清单**（反向判定）：
- 服务器随机密钥（每次变化、无法解密/签名）→ 不进清单
- 图片验证码可获取 → 预授权正常业务
- 系统时间、空列表/空对象、通用错误提示、格式校验结果 → 不进清单（差异错误枚举最多 low）
- 前端 UI 可访问 → 前端组件不算越权
- 字典/枚举仅代码+名称 → 默认 low，含敏感配置才升 medium+

**预授权 vs 后授权是核心分界线**：业务位置在「用户输入凭证/扫码/打开页面」**之前**的无认证是设计预期（系统时间、验证码、注册、登录前必要接口），**不**单独报「未授权」；创建/退款订单、用户资料、我的订单、资金/积分写操作是后授权，缺认证才是问题。

**XSS 三条件**：① 输入确实进入 HTML/JS/CSS 上下文（须确认前端 `innerHTML` vs `textContent`，只看 JSON 响应不够）② 转义被绕过（至少试 3 种上下文姿势才可写"无法绕过"）③ 有实际执行环境。误报红线：只测一种 `<script>alert(1)</script>`、只被 WAF 拦就推断后端安全、滤了 script 未试事件处理器。

**措辞禁用词**：「未授权访问漏洞」（太泛）、「任意用户订单查询」（要说清返回哪些字段）、「可导致资金损失」（除非已验证真实资金变动）、「密钥泄露」（除非已验证可用于实际攻击）、「部分覆盖/基本完成/待后续验证」（改 BLOCKED/NEEDS/N/A）。

**样本硬上限**：越权读 1–3 条自有或测试号；SQL 注入最多 1 个字段名证明可读；高危 ≥3 次复现。
