**经验**：kb 条目的 `source:` 字段同时是**出处署名**和**作用域声明**，两件事别混。检索时靠 description 命中，但**命中之后要回读 `source:` 确认这条经验属于哪个项目/组件/版本**——命中即适用是错的，跨项目套用必须实测。写条目时如果只写"某类系统普遍如此"，就等于把作用域写没了。

**Why**：`llm-context-window-is-input-plus-output` 的 `source:` 写的是 "APIShow AstrBot v4.28.2 tdp 网关（qwen3.8-27b）"，作用域本该很窄；但正文第一句写的是"**OpenAI 兼容上游普遍**按 `input + max_tokens ≤ window` 校验"。"普遍"两个字把 AstrBot 单点结论包装成了通用规范。迁移 DSH 桌面端配置时我检索命中这条，看到阶跃星辰2 的 `step-5-preview` 是 `maxTokens 1000000 == contextWindow 1000000`，就断言"任何有输入都会在校验阶段 400"，还把 maxTokens 主动从 1000000 压到 65536——**StepFun 是否做这个校验从未实测**。用户纠正："这个经验不是这个项目的，是 AstrBot 那个项目的，要分清。"

同一轮我还有两处越界，性质相同：①用 AstrBot 教训反推用户的 DSH 配置"踩了坑"，实际上 65536→1000000 是用户有意改回；②以"ZCode 里没声明图片能力"为由提醒 workbuddy 的 glm-5.3-flash 加图片输入有风险，实际上该网关确实支持且已声明。**三处都是把别处的事实/默认当成对当前项目的判断**——方向一致：拿来源当结论用。

**How to apply**：

1. **写入时**：条目正文的陈述句必须带作用域限定词（"在 X 项目/该网关/该版本下"），不要用"普遍/一般/通常"这类词替来源署名。`description:` 里也要带作用域标记，例如 `【作用域=AstrBot tdp 网关 + qwen3.8-27b，跨项目未验证】`——description 是检索用的，限定词得留在检索面，否则命中时看不到边界。
2. **跨项目套用前**：先回读 `source:`，问一句"这条的实测环境和我现在面对的环境，哪些变量不同"（上游网关、模型、协议、框架版本）。变量不同就要实测，实测之前只能说"可能"，不能说"会"。
3. **改别人已设的值之前**：配置项被改动过一次后，第二次改动前要判断这是**用户有意为之**还是**待修缺陷**。判据：用户改的值有没有明确偏离我上次的建议——如果偏离了，说明用户在跟我商量或已经知道后果，别把自己的推论又推回去。要问就问，不要"顺手修正"。
4. **发现旧条目作用域写宽了**：把限定词补回 description 和正文首句，并在条目里加一条"已发生的误用"记录（含日期、误用场景、我错在哪）——误用记录比教训本身更有检索价值，下次能靠它命中。
5. **⛔ 修了一条 ≠ 修了这个家族（2026-09-30 二次犯错）**：用户第一次纠正后，我只给「上下文窗口 = 输入 + max_tokens」那一条补了作用域标记，**没有回头找同族兄弟**——结果「思考型模型 reasoning 与正文共用 max_tokens 预算」那条（同属模型参数、同属单模型实测、同样写成通用定律）原封不动留在库里，被用户第二次点名才修。**所以每次加作用域标记，必须顺手做两件事**：①`grep -ril "同主题关键词" ~/.agents/kb/` 检索同族，逐条问"这条 `source:` 是几个来源？一个就要标"；②把**判断标准**写进本条，而不是只写这次的案例。
6. **⚠️ 反向陷阱：单来源 ≠ 伪通用，别过度矫正**。kb 的收录标准就是"跨项目可复用"，所以**绝大多数条目本来是通用规律、只是碰巧在某个项目里踩到**（bind mount 属主、克隆整行带模板残留、全量 PUT 抹掉脱敏字段、手写 P-256 那些）——这些**不该**加作用域，硬加只是噪声。**真正要标的只有一类**：`description` 里出现了**具体的数值上限、错误码、返回结构、字段名**，却没点名它属于哪个网关/模型/平台。2026-09-30 按这条标准扫 110 条，真正要修的只有 **2 条**（`reasoning-model-max-tokens-shares-budget` 的"content 键整个不存在"形态、`quota-exhausted-vs-banned-distinguish` 的 New API 业务码 14018/11140）。**别为了显得严谨给通用规律贴作用域标签。**
7. **相邻教训**：来源不是规格见 [[config-field-name-is-not-spec-read-consuming-code]]（字段名）、[[log-text-is-not-spec-read-emitting-code]]（日志文案）——本条是同一个模式的第四面：**经验库条目的 source 也不是它的作用域扩展**。
