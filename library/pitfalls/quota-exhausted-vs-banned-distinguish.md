**经验**：一个号"不能用"有两类根因，**症状、判据、可行的处置完全不同**，混为一谈会白试修复动作。

| | 额度耗尽 | 账号级封禁 |
|---|---|---|
| 症状码 | `429` + 业务码 `14018 额度已用尽` | `403` + 业务码 `11140 request illegal` |
| 判据 | 资源端点显示余量为 0 | **换模型、换提示词、换流式开关全部同码拒绝** |
| 例 | 12 个包全 `CycleCapacityRemain=0` | 29 个模型 29 次全 403，一个不剩 |
| 可恢复？ | 等周期性补给（签到/任务/充值）；无补给则永久 | **否**——非配置可解，只能弃号 |
| 处置 | 摘除待观察 | 直接清除 |

**Why**：三条实测教训：

1. **⛔「余额还能查」≠「账号还能用」**——被 403 封禁的号，资源端点仍正常返回 4092 分。**别拿余额存在当账号健康的证据**；要单独测一次真实调用。
2. **别把"换模型能过"当判据**：单个模型报错可能是模型级问题（本例另有一批模型名在目录里存在、实际调用返 `400 code=11102`「模型不存在」，与封禁无关）。**账号级封禁的特征是"全模型一致同码"**——跑一轮全模型体检，整齐划一地同码即账号问题。
3. **别把首两三次失败当瞬时故障反复重试**：间隔数分钟复测 2~3 次仍同码即持续态，停止重试。

**How to apply**：
1. 遇 4xx **先取业务码**（`error.data.code` 或顶层 `code`），再决定动作——HTTP 码相同、业务码不同则修法不同。
2. 疑似账号级问题：对**该号可用模型全集**逐个最小请求，统计"同码占比"。全部同码 ⇒ 账号级。
3. **先测可用性再花钱花时间**：接入新号后第一件事是"最小实打 + 全模型体检"，通过后才配渠道/写文档。
4. 做体检脚本时带上**对照号**（已知可用的号跑同一组模型）：对照号通过而目标号全拒 ⇒ 隔离出账号因素，同时证明"探测方法本身没问题"。
