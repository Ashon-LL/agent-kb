**经验**：对比两个「由同一份源码重新构建/重新混淆」出来的产物时，**逐字 diff 基本失效**，
必须锚在跨构建稳定的特征上，否则会把「重命名噪声」当成「功能改动」，
或者更糟——把真实改动当成噪声放过。

## 一、实测：三种 diff 手段的失败形态

同一对产物（上游重发了一版修复包，CLI 15.6MB）：

| 手段 | 结果 | 为什么失效 |
|---|---|---|
| 块哈希 diff（4KB 块 + SequenceMatcher） | 27 个「变化区」几乎全是假差异 | 整体重新混淆，局部变量名一改，后续字节全部错位 |
| 字符串字面量集合差集 | 3060 增 / 3026 删，**几乎全是噪声** | 短标识符被整体改名（`E6e`→`E0n`），字面量里混进了内嵌代码模板 |
| 「含中文且短」的字面量差集 | 真的捞到了新增用户文案 | 手工写的中文文案跨构建稳定 |

反过来，**稳定锚点**实测有效：

1. 作者自己写的**接口/标记名**（如 `isZsmRetryableInferenceInvalid`、`zsm-notify-test`）——
   两版集合完全一致，据此立刻判定「CLI 的 IPC 面没变，新能力是纯逻辑，不新增接口」。
2. **注册名**（`r(fn,"inspectCompactSummaryText")` 这类导出注册）——能定位到被混淆后的实现。
3. **常量**（`maxAttempts:1e5`、`{402,413}` 这类集合）——直接读出策略。
4. **作者的发布说明**（manifest/release notes）——是变更清单的一手来源，但**必须再用产物核实**，
   因为发布说明可能夸大（实测：说明里写「恢复重试抖动」，产物常量却是 `jitter:!0`）。

## 二、How to apply

1. 先用**作者口径**（功能页 + release notes）固定验收清单，再逐条去产物里找实现；
   找不到就标「未在产物中核实」，**不要**当成已具备。
2. 差异定位顺序：**文件级大小变化 → 稳定标记/接口集合 → 手写文案 → 常量 → 注册名 → 最后才逐字符**。
   前四步能覆盖绝大多数真差异，且不会被重命名污染。
3. 判定「某能力有没有」时，用**存在性 + 行为**双证据：符号在 ≠ 行为对；
   要把实现抽出来跑（这次正是靠抽 `inspectCompactSummary` 真跑，才确认阈值是 200 字 / 2 段落 / 4 编号项）。
4. 发布说明与产物冲突时，**以产物为准**，并把冲突写进报告（例：上游说「恢复抖动」，产物 `jitter:!0`）。
5. 差异分析要能回答「谁更强」：同一条功能要对比**双方的判据强度**，不是只看有没有。

## 三、配套：这类任务里最容易漏的两类真缺口

- **只有文案判据、没有状态码判据**：可重试判定若只匹配错误文案，401/403 会被改写成可重试，
  配合 `maxAttempts:1e5` 就是数小时空转。判据必须同时看状态码。
- **多路外发写成串行**：`results.push({ch, ...await p1})` 再建 `p2` —— 第二个请求根本没被创建。
  验证方式不是「结果都在」，而是**时间序断言**（后一个渠道的发起时间 < 前一个渠道的完成时间），
  并配**变异反证**：把实现改回串行，测试必须红。


## 四、两条最容易犯的对比错误（本轮实测各踩一次）

1. **拿对方的「变更清单」当验收基线**。对方发布说明只写它这次改了什么，
   没写的既有能力照样可能有你没实现的功能——用清单对照 = 主动漏检。
   正确姿势：把对方的**完整功能清单**（功能页/文档全量条目）当基线，再用产物核实每一条。
2. **符号名差集 ≠ 能力差集**。我方 `askDeepSeek`/`deliverNotify`/`loadRouteMemory` 与对方的
   同名不同写，实测「对方独有符号」里有大量我方已有等价实现；反过来，**官方 3.18.0/3.18.2 都有的
   一整套机制**（如工作区释放 `requestWorkspaceRelease`/`hasRunningTasks`）在符号差里完全看不见，
   差点被写成「对方的实现」。归属必须做**多树交叉**：官方两版都没有 ⇒ 才是该方自研；
   官方也有 ⇒ 是上游机制，**不能记成对方的实现**。
3. **对照要落到能力层，不是符号层**。最终结论用「能力矩阵（对方全量条目 × 我方状态）」，
   符号面只用来发现清单之外的遗漏（例如发现「我方 UI 写 `x-zsm-path`，CLI 却 0 命中」的**死链**）。
