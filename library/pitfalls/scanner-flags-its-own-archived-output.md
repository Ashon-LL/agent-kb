**病症**：仓库的安全门禁（敏感信息扫描）**长期恒 FAIL，且怎么清都清不掉**。

**病根**：**门禁在扫门禁自己的历史输出。**

## 事故经过

本仓 `scripts/release_check.py` 有 2 项恒 FAIL。逐条查那 5 条硬失败，
**全部**来自同一个文件 —— 一份**证据文档**里用 ` ``` ` 代码块**原样粘贴的门禁历史输出**：

```
[FAIL] 1. 工作区敏感信息
       docs/.../README.md:275 [本机绝对路径泄漏] '<本机路径>'      ← 门禁自己的输出
[PASS] 2. git 历史敏感信息
  [提示] git 历史提交仍含 '<站点名>'（HEAD 已清除）——建议择期 history rewrite：...
```

⇒ **一个真实泄漏都没有。**

**闭环**：证据文档**如实存档「门禁当时报了什么」是正确行为**（证据就该原样留档），
但这让 **门禁的输出变成下一次门禁的输入** ⇒ **恒 FAIL**；
而且**清不掉** —— 你清掉这次的文本，下次贴新报告**又复发**。

## ⛔ 为什么「改报告」治不了本

第一反应是去改述那份报告。但：
- 报告**本来就是证据**，改述等于**篡改自己的证据链**；
- 更致命：**下次贴新门禁输出，同样的字面量又回来了**。

⇒ 必须**同时改门禁**。

## 三层修法（按需取用）

**① 删「过度敏感」的模式 —— 按真实脱敏口径收敛**
本例用户口径是「**脱敏 ≈ 只禁密钥**」（站点/域名/产品名**可暴露**）。
那站点名模式**本来就不该在门禁里**：它既非凭据、又不是秘密，
唯一效果就是**制造自指假阳性**。删掉，假阳性源头消失。
⛔ 但要**保留真秘密**：`sk-` 密钥 / `Bearer` / 硬编码 `api_key` / 本机绝对路径。

**② 加「证据目录豁免」—— 按目录，不按文件名**
```python
EVIDENCE_PATH_PREFIXES = ("docs/harness-evidence/",)
_SECRET_ONLY_PATTERNS = {"疑似真实 API 密钥", "疑似 Bearer Token", "疑似硬编码 API Key"}

def _is_evidence_doc(rel: str) -> bool:
    return any(rel.startswith(p) for p in EVIDENCE_PATH_PREFIXES)

# 扫描时：
if _is_evidence_doc(rel) and desc not in _SECRET_ONLY_PATTERNS:
    continue        # 证据文档只豁免「非密钥」类；密钥照扫
```
⛔ **关键**：豁免**只对非密钥类生效**。证据文档也**不能**存真凭据。
⛔ 且**只豁免明确的证据目录**，不得放宽成「某类文件名」或全仓豁免。

**③ 输出占位化 —— 存档时就把字面量换成占位符**
```markdown
> ⛔ 改述说明：下方逐字保留当年门禁的实际输出形态，但把站点名/路径**占位化**。
```
```
[提示] 仍含 '<曾用中转站点A>'（HEAD 已清除）——建议择期 history rewrite：...
```
语义不变，只字面量占位化 ⇒ 将来再被扫到也不会命中。

## ⛔⛔ 验收纪律：必须做「防修成假绿」的反证

修门禁最容易的翻车方式 = **把门禁修成了恒 PASS**（比恒 FAIL 危险得多）。

**必须跑两道反证**：

| 反证 | 注入什么 | 期望 |
|---|---|---|
| **防假绿** | 在**普通路径**放真 `sk-` 密钥 / `Bearer` | **必须 FAIL** |
| **豁免边界** | 在**证据目录**放 真密钥 + 站点名 + 本机路径 | **密钥被抓、站点名与路径放行** |

本例实测：
- 防假绿 ⇒ `[FAIL]` 并准确报出两条 ✅
- 豁免边界 ⇒ 密钥被抓、站点名/路径放行 ✅

⇒ **只有两道都过，才算「修对了」而不是「修哑了」。**

## ⛔ 元教训：审计发现了病根却不修 = 没发现

本仓 **0911 的审计文档**（`audit-20260911/RELEASE_DOCS_CHECK.md`）**已经明确写出**
「扫描器自命中，属代码侧问题，移交修复工程师」—— 然后**挂了 8 天没人修**，
期间门禁一直 2 项 FAIL，把**真信号淹在噪音里**。

⇒ **审计产出的"待修项"必须有归属与截止**；只记录不派单，
等于给系统留了一个**长期假警报**，而假警报会训练人**忽略门禁**。

## How to apply

- 门禁**长期恒 FAIL** 且「清了又回来」⇒ **先怀疑自指**：
  门禁的**输出**是否被存档进了**被扫描的范围**？
- 修法**三层同时做**：删过度模式 + 目录级豁免（密钥类不免）+ 输出占位化。
- 修完**必做两道反证**（防假绿 / 豁免边界）⇒ **别把门禁修哑了**。
- 审计发现的问题**要派单**，别让它烂在文档里。
