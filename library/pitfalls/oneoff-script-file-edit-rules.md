**经验**：一次性脚本改配置/凭据/DB 相关文件时——

1. 改前做**独立备份，且脚本重跑绝不重新生成/覆盖该备份**（备份前先查存在性，存在即跳过）。
2. 段式文件（TOML/INI 按 `[header]` 分块）重写必须**逐段重发段头**；写后立即校验关键段头与关键字段仍在。
3. 文本重写优先"读全→全量替换→校验"，不用增量拼接；能用原生 API（PUT 目标字段）就不写文件；改完当场重读验证——**别拿"写入成功"当"内容正确"**。
4. **编辑工具对含特殊字符/不可见字符（`→`、`—` 等）的区块反复 ExactMatch 失配**时别死磕——先打印目标行 repr（或按行号定位）看真实字符，然后换 Python 按行/字节替换（`lines[i]` 定位、`.replace(old.encode(), new.encode())`）。

**Why**：真实事故——按段重写脚本漏写未改动段的段头，把双端配置全吞；二次重跑又把已坏文件覆盖了唯一完好备份，差点无法恢复。
