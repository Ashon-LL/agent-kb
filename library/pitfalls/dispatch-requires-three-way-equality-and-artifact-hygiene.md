# 派单前核三方等值 + 载荷先入仓 + 产物落项目内（用户 20261021 连斥三条）

**现象**（用户原话）：
- 「**本地有未上传的为什么不上传再派单？**」
- 「本地已有 7 个未推提交（`20430d84`、`b4aedec1` 及更早 5 个）你知道
  吗？**为什么要搞偏移**！！！！！！！」
- 「一定要放在 `<项目文件夹>`……**不是其他地方，不是 `~/.zcode/workspace/<项目>/`**！！！……
  做好项目卫生，不要到处乱放产物！！！」

**根因（三条，都是我的流程缺口，不是误解）**：

1. **等值核验的时机错了**：我在**自己每次 push 之后**都核过 local/bx/origin 等值 —— 但
   **派单前没有重新核**。而派单意味着**外部执行者开始写同一个仓**：那次派单后 87 秒内
   目标仓就多了 3 个提交（我的任务书成了它们的父提交），本地还另有 1 个未推提交
   ⇒ **三方分叉**（local 有 A，bx 有 B+C+D，origin 停在共同祖先）。
   教训：**「我上次核过」在派单语境里一律无效**；宿主的等值只是**某个时刻的快照**，
   任何外部执行者动作之后就过期。
2. **载荷传递用了旁路**：执行者在容器里**没有平台登录态**，我拿一次性签名 URL 让它 `curl`
   —— 会过期、不可复现、且与"产物必须在项目内"自相矛盾。正解是**先入仓再派单**
   （`docs/dispatch/attachments/`，并写清许可证与清理条件）。
3. **产物散落在项目外**：`ego/`（43 M 暂存包 + 派单 payload）不在项目目录里。
   正解：项目内 `_tmp/`（**先确认 `.gitignore` 有规则**，否则会污染未跟踪列表）。

**怎么防（可复用的四步）**：
1. **派单前三方核**：`git fetch` 两远端 → 比 `local` / `开发主场` / `发布线` 三个 SHA；
   **不等就先统一**（rebase 到主场之上 → 推两仓 → 再核一次），绝不带着分叉派单。
2. **载荷先入仓**：执行者要用的东西（技能包、夹具、素材）**提交进仓**并在任务书里给**仓库内路径**；
   ⛔ 不用签名 URL、不进 `_tmp`（`_tmp` 是 gitignored，执行者读不到）。
3. **产物落点唯一**：`<repo>/_tmp/`（先补 `.gitignore` 规则）。⛔ 不写 `~/.zcode/workspace/`、
   `~/ego/`、`%TEMP%` 或任何项目外目录。
4. **派单后立刻重核**：目标仓会被执行者推进 ⇒ 第一时间再比三方，发现分叉就地统一
   （并保留 `backup/pre-unify-<date>` tag 作退路）。
